# 后续配置与真实硬件接入指南

本指南对应当前已实现的配置，避免把原提示词中的示例结构误当成现有程序可直接读取的结构。真实 EtherCAT、CANopen、RM75、RS485、RealSense、LiDAR 后端仍是预留接口。通用 UVC 摄像头已实现 `backend: uvc`，使用方式见 [笔记本摄像头测试](笔记本摄像头测试.md)。

## 2. Robot A 相机 4 / 5 路切换

A 的配置包含 camera_1～camera_5，B 包含 camera_1～camera_3。将 A 的第五路改为：

```yaml
cameras:
  # 保留原来的 camera_1～camera_4 条目
  camera_5:
    enabled: false
    backend: mock
    fps: 5
    label: ROBOT A CAMERA 5
```

这是配置片段，不要把它覆盖整个 YAML。第五路改为 true 即恢复 5 路，其他相机编号不改变。不要为了减少数量把 camera_5 改名成 camera_4。

| 字段 | 作用 / 约束 |
|---|---|
| cameras 下的 key | 相机稳定 ID；以字母开头，只能有字母、数字、下划线；不能和轴/硬件/System/heartbeat 重名 |
| enabled | true 启用；false 时不创建设备、采集线程、订阅和预览 |
| backend | 当前使用 mock；real 仍未实现 |
| fps | 建议 5；采集周期按 1～10 FPS 限制 |
| label | Mock 图像里的名称；界面标题保持 Robot + camera_id，悬停显示 label |

相机 topic 为 `/<robot_id>/cameras/<camera_id>/image_raw`；Diagnostic 和故障选择器的设备名为 camera_id。将来的 USB serial、设备路径、IP 等字段尚未被 Mock 使用，只有对应真实 Adapter 实现读取后才生效。当前 1080p 布局针对 A5+B3 共 8 路验证，增加更多相机需重新验证布局和通信负载。

## 3. 电机和总线

```yaml
hardware:
  ethercat:
    enabled: true
    backend: mock
axes:
  drive:
    bus: ethercat
    max_velocity: 0.2
    jog_velocity: 0.1
```

- `bus` 关联 hardware 中的总线；轴默认继承该总线 backend。
- `hardware.<bus>.enabled: false` 会同时关闭该总线和它的轴，手动轴选择器不再列出这些轴。
- `jog_velocity` 是手动按键速度的绝对值，应为正且不大于 `max_velocity`。
- `max_velocity` 是指令接受上限，超限、NaN、无限值被拒绝，不刷新 Watchdog。
- 当前所有位置/速度均为 Mock 的线性模拟单位，不能把数值直接用于真实编码器、电机转速或机械臂关节。转换比例、方向、限位属于真实 Adapter 的职责。

A 默认 drive、clamp_left、clamp_right、z_axis。B 增加 support_left、support_right，归属 CANopen。

## 4. Watchdog、Heartbeat、Diagnostics

```yaml
test:
  watchdog_timeout_ms: 500
  heartbeat_hz: 1.0
  diagnostics_hz: 5.0
```

Watchdog 当前允许大于 0 且不超过 500 ms，JOG 和 Auto 都受保护。不要把它设得比地面站 100 ms 命令周期还短。Heartbeat / Diagnostics 频率必须大于 0，建议保持默认；Heartbeat 太慢会触发地面站固定 3 秒离线判定。

以下当前是代码常量，**不要只向 YAML 添加同名字段并期待生效**：

| 参数 | 当前值 / 位置 |
|---|---|
| Ground JOG / Auto 保活 | 100 ms，ground/app.py 的 jog_timer |
| Offline 判定 | 3 秒，ground/bridge.py 的 RobotViewModel.online |
| 相机 stale 判定 | 2 秒，ground/camera_panel.py |
| Agent 控制检查 | 10 ms，agent/node.py |
| CSV 状态记录 | 1 秒，agent/extensions.py、ground/bridge.py |

这些路径均位于 `ros2_ws/src/robot_test_<ground或agent>/robot_test_<ground或agent>/`。

## 5. Auto Cycle

```yaml
test:
  auto_cycle:
    enabled: true
    axis: drive
    positive_target: 1.0
    negative_target: -1.0
    velocity: 0.1
    dwell_sec: 1.0
```

axis 必须是启用的轴；positive_target 必须大于 negative_target；velocity 大于 0 且不超过该轴 max_velocity；dwell_sec 不小于 0；数值必须有限。每台机器人目前一次只自动测试一个轴。停止并重新启动 Auto 会从 MOVE_POSITIVE 状态开始，依据当前位置走向正向目标，不会自动把位置清零。

## 6. 日志和会话

`ROBOT_TEST_SESSION` 可在启动脚本前设置，三端使用同名 session 方便归档。

```bash
export ROBOT_TEST_SESSION=magnetic_field_001
./scripts/start_mock_demo.sh
```

默认日志根目录在 `scripts/env.sh` 中设为项目 `logs`。如需其他位置，可修改该脚本的 `ROBOT_TEST_LOG_ROOT`；或者先 source 后覆盖，再直接 ros2 启动。脚本会再次 source env.sh，因此仅在脚本前 export 另一个根路径会被覆盖。不要用路径分隔符作为 session 名。

## 7. 多机部署准备

三端都安装同版本工程并构建：A 只运行 A Agent，B 只运行 B Agent，Ground 只运行地面站。三端的 robot_id、namespace 和 Ground 中的 YAML 应一致；当前没有动态发现相机清单，改相机数量需同步 Ground 配置。

ROS_DOMAIN_ID 三端保持一致；跨机器时不要保留测试使用的 ROS_LOCALHOST_ONLY=1。当前只验证了单机 DDS，5G 网络是否支持节点发现、UDP、多播和防火墙通行需现场验证；本项目未加入 DDS Router、Zenoh 或公网通信方案。先用同网段局域网验证，再评估 5G。三端系统时间应同步，尤其 JOG 时间戳会拒绝过旧或未来指令。

## 8. 真实硬件 Adapter 开发步骤

**单独把 backend 改为 real 不会完成硬件接入。** 当前 real 类在 connect 时明确报未实现错误，也不回退到 Mock。

1. 先明确设备参数：型号、连接方式、驱动/SDK、轴映射、单位、方向、限位、相机序列号及接口超时。
2. 实现 MotorAdapter / CameraAdapter / DeviceAdapter 的契约。电机要支持 connect、enable、disable、jog、stop、位置/速度/错误/状态；相机要支持连接、取帧、FPS 和累计计数。
3. 一个总线会话应服务同总线的多个轴，不要为每轴重复抢占同一物理主站。总线会话的创建和共享放在 Factory/backend 内部。
4. 相机 get_frame 在独立线程执行；状态查询、断开和故障处理必须线程安全。其他 Adapter 的 update、stop、get_status 必须有界，不能阻塞 Agent 本地 Watchdog。
5. 在 factory.py 注册构造器。电机 real 的 bus 映射指向 EtherCATMotorAdapter / CANopenMotorAdapter；相机等指向相应设备类。设备专用参数从对应 YAML 条目传入。
6. 驱动内部实现真实计数、断线重连、读写超时；异常转为诊断状态。恢复连接不应擅自恢复运动使能。
7. 单独完成驱动的停车、失联保护、限位测试后，再把对应总线/设备 backend 改为 real。修改相关配置后重启。
8. 检查上层 namespace、JOG、STOP、Auto、Diagnostics、Event CSV 行为保持一致；尽量不改 Agent/Ground 业务逻辑。

RM75 / RS485 当前仅有通用状态和通信计数，没有真实作业命令；如需新增任务指令，须先扩展明确的 Adapter API 与测试，不能直接在 ROS callback 中写 SDK 调用。LiDAR 仅有真实类预留，无当前扫描数据可视化。

## 9. 修改后的检查清单

```bash
cd /home/tian/robot_test_system
source scripts/env.sh
python3 -m unittest discover -s tests -p 'test_*.py' -v
ROS_DOMAIN_ID=86 ROS_LOCALHOST_ONLY=1 QT_QPA_PLATFORM=offscreen \
  TEST_LAYOUT=1 TEST_P1=1 ROBOT_TEST_SESSION=config_validation \
  python3 tests/acceptance_p0.py
```

该命令启动独立域的 Mock 子进程，不连接真实硬件。不要把真实 backend 配置直接用于 Mock 验收脚本。改成真实后需另做现场验收：先停车/失联，再手动低速，最后自动运动；保持硬件急停可用。既有软件测试通过不代表真实机器人安全验收通过。

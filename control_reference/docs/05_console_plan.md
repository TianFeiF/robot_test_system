# 地面站控制台开发拆分方案

目标：地面站负责操作者交互、命令调度和状态呈现；两台机器人继续各自拥有硬件驱动和本地停车逻辑。测试工程保留为回归基线。以下是开发方案，不表示这些新模块已经实现。

## 建议结构

```text
新控制工程/
  console_ui/          双机总览、各机器人操作页、视频、告警、参数显示
  control_client/      ROS连接、异步请求、命令队列、状态与帧缓存
  task_controller/     作业动作、取消、资源互斥、超时与恢复
  robot_backend/      复用Agent/真实适配器，后续独立重构
  interfaces/         初期复用robot_test_msgs，新增接口保持兼容
  config/             设备拓扑、命令范围、维护状态；与标定分开
  calibration/        各机器人独立持久零点和版本（从现场核实后迁入）
  tests/              Mock回归和驱动假SDK测试
```

初期推荐延续现有PySide6和ROS2 Humble，先替换地面站界面，保留机器人端协议，减少硬件和UI同时迁移带来的问题。不要仅因包名带test/mock就删除：`robot_mock_hardware`内有真实驱动，`TestExtensions`里还包含日志计时器和旧自动接口。

## 可以直接复用

- 原生EtherCAT/CANopen驱动、单位换算、命令序号、反馈读取、停车确认、看门狗。
- factory与适配器抽象、RGB设备发现和掉线重连、雷达统计、RM75状态读取。
- ROS消息定义与Agent基本控制服务、诊断格式。
- GroundBridge的线程模型、STOP优先队列、命令generation、服务结果回传、相机最新帧缓存。
- CSV/事件记录和现有模拟回归；以后可另加操作审计，不丢弃现场问题定位能力。

基线中不修改包名；若后续迁移为 `robot_hardware` 等，需要同步setup.py/package.xml、imports、启动脚本和部署检查，逐步验证。

## 留在测试工程的部分

自动周期测试（AutoCycle）、Mock故障注入、测试标记按钮、压力/验收脚本保留，但不放进常规驾驶操作路径。尤其不能把 `start_auto` 作为“机器人启动”或“任务开始”的通用实现，它同时作用多个轴并按测试参数周期反转。

`test.watchdog_timeout_ms`等安全相关参数虽然位于test段，初期仍必须读取；迁移时将安全参数拆出，不能删除test段后让看门狗失效。

## 控制台首版范围

| 模块 | 首版应实现的行为 | 当前可复用基础 |
|---|---|---|
| 双机总览 | A/B分别在线状态、模式、维修状态、总线错误 | heartbeat/diagnostics |
| 手动控制 | drive/Z速度、左右夹持及B支撑力矩，持续按压与松手STOP | arm/jog/torque/stop |
| 维修状态 | 展示A Z故障记录，区分“自动禁用”和“所有操作禁用” | 当前配置只有自动enabled |
| 回零页面 | 独立HOME与ZERO入口、进度、取消、真实完成状态 | worker已有；进度/互斥协议待补 |
| 视频 | A四路/B三路RGB、采集与接收FPS、新鲜度、重连 | camera_panel与frame_stats |
| 停止与告警 | 单机器人STOP、双机器人STOP、超时未确认、错误详情 | stop优先队列及诊断 |
| 雷达/机械臂 | 当前仅状态信息 | LivoxMonitor/RM75Monitor |

力矩“保持”“松开”、夹持/支撑联动顺序、故障时的实际机构策略需要在具体任务定义中明确。保留现有测试停车行为作为兼容性事实，不能直接称为正式作业策略。

## 开发顺序与验证点

1. **只读控制台**：双机连接、状态、7路RGB与告警；禁止启动测试循环；用Mock断流/重连验证旧帧不会冒充实时画面。
2. **手动控制**：对现有服务和topic封装CommandGateway；确认左右符号、单位、速度/力矩边界、过期命令拒绝、松手停车和STOP反馈。
3. **回零与标定管理**：显式HOMING状态，互斥ARM/Auto/第二次回零，区分已开始与完成；零点更新核验及持久化。A维修状态在恢复前保留。
4. **任务动作**：明确工作步骤后再引入ROS Action/任务状态机、取消与中止、单轴或分组保持策略。不要复用5秒反转的测试循环当作业逻辑。
5. **扩展设备**：机械臂运动、经机械臂RS485末端控制、点云显示分别增加实现；保留驱动厂商资料、报文与单位标定。

## 源码审阅发现的迁移事项

- controller.arm会调用所有motor.enable，硬件层可能只是总线ARM；不能据 `armed=True`推断每轴已经使能。
- EtherCAT每轴stop影响整个共享总线；单轴停机需要明确新增设计。
- 回零线程与普通controller/服务之间尚没有完整资源互斥。正式控制台要先处理此项，再开放任务联动。
- `set_z_reference()`当前等待 `z_referenced` 标志，原生遥测没有回传精确零点和ZERO请求关联结果；标定保存确认应补充精确应答。
- `home_z`无ROS Action终态；旧事件日志不足以成为操作反馈协议。
- 当前状态故障可能包含视频错误；界面应区分运动故障与可选传感器告警。
- A/B停止不是原子同步动作；真正的双机协同动作需要任务层协议，不能只同时点两个按钮。
- 两台机器人SDK与现场源码本次尚未取回，先补证据再进行后端大规模重构。

这些是迁移时需要处理的事项，本次仅整理与冻结，没有悄悄改动现有运动代码或现场配置。

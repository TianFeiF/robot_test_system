# 双机器人硬件测试 Demo 使用指南

适用版本：2026-09-17。当前是软件 Mock，A 默认 5 路相机、B 3 路；机器人真实驱动还未接入；笔记本摄像头已支持 UVC 接入，见 [笔记本摄像头测试](笔记本摄像头测试.md)。

## 1. 启动和退出

打开终端：

```bash
cd /home/tian/robot_test_system
./scripts/start_mock_demo.sh
```

会同时启动 A/B Agent 和地面站，地面站默认全屏。1920×1080、100% 显示缩放下，可以同时看到所有当前设备行、8 路相机、控制按钮、事件按钮和最近日志。更大分辨率也可使用；不要启动两份同 namespace 的 Agent。

- **F11**：全屏与窗口模式切换。
- **Esc**：退出全屏，程序继续运行，不等于 STOP。
- **EXIT / STOP ALL**：请求两机器人停车，然后关闭窗口和由同一脚本启动的 Agent。
- 停车请使用 **STOP / STOP ALL**。切换窗口会停止当前手动 JOG，但已经启动的 Auto 会继续，直到明确停车或保活超时。

完整历史日志可以滚动查看，也保存在 CSV。界面显示每类设备的关键计数；鼠标悬停单元格可查看原始完整诊断值和故障详情。计数过长时以原始提示和 CSV 为准，有限屏幕不可能同时展示无限日志历史。

## 2. 认识界面

从上到下：

1. A/B 在线状态、机器人状态、控制模式、最近 Heartbeat 距今时间和 uptime。
2. 两张设备表：Device、State、Position、Velocity、Status / Counters。位置和速度保留四位小数，原始精度仍在提示和 CSV 中。
3. 相机横排：A camera_1～5、B camera_1～3，各自画面、状态、FPS 和帧计数。
4. 机器人/轴选择、JOG −、STOP、JOG +、STOP ALL。
5. Auto 测试、Mock 故障注入、事件描述和事件标记。
6. 最近的操作结果和错误日志。

绿色表示正常，黄色表示 WARN，红色表示 ERROR / OFFLINE，灰色表示 UNKNOWN。机器人超过 3 秒无 Heartbeat 判为 OFFLINE，重新收到心跳自动恢复。故障相机或超过 2 秒没有新帧时清空对应预览，其他相机继续显示。

常用计数字段：

| 设备 | 界面字段含义 |
|---|---|
| System | armed：是否使能；mode：MONITOR / MANUAL / AUTO_TEST；auto：往复状态 |
| 电机 | enabled：是否使能；err：累计故障；reconnect：累计重连 |
| 相机 | FPS、frames：累计帧；drop：丢帧；disconnect / reconnect：断线 / 重连次数 |
| EtherCAT | cycle：循环；err：错误；lost：从站丢失；recover：恢复 |
| CANopen | msg：报文；timeout：超时；err：错误 |
| RS485 | req / resp：请求 / 响应；timeout：超时；CRC：校验错误 |
| Network / RM75 | rx / tx：收发；timeout、err、reconnect |

这些是模拟计数，不是真实总线测量。计数按 Agent 进程累计，重启归零，已有 CSV 不覆盖。

## 3. 手动 JOG 与停车

1. 确认 A/B ONLINE、目标运动设备正常。
2. 选择 `robot_a`、`drive`。
3. 按住 JOG +：Velocity 为正、Position 连续增加；按住 JOG − 则反向。
4. 松开按钮后停车；也可按 STOP 停止选中机器人全部轴。
5. STOP ALL 对 A/B 都发送停车指令，取消自动运动并解除使能。

地面站按住时以 10 Hz 发送 JOG。Agent 默认 500 ms 收不到有效指令即停车；STOP 后残留 JOG 指令不能重启运动，需重新按下 JOG 或明确启动 Auto。界面观察到零速还可能包含 Diagnostics 的采样延迟。

**软件 STOP 不替代硬件急停。** 当前只验证 Mock；真实设备必须有驱动器独立保护、限位和硬件安全回路。

## 4. Auto Cycle

选择机器人，点击 START AUTO TEST。自动轴来自该机器人的 YAML `test.auto_cycle.axis`，**不是当前手动 AXIS 下拉框**。

默认 drive 以 0.1 速度向 +1.0 运动、停 1 秒，再向 −1.0 运动、停 1 秒，重复。可同时启动 A/B。STOP AUTO TEST 和 STOP 停止选中机器人，STOP ALL 停止两台。地面站持续发送 Auto 保活，丢失 500 ms 会停止。

## 5. 故障注入和恢复

选择机器人，在 MOCK FAULT 选择设备，点 INJECT。检查对应行变红或变黄，再点 RECOVER。

- camera_1 等：只断开所选一路相机，恢复后重连次数增加。
- ethercat / 电机 / canopen：注入运动设备故障，会停止运动；恢复后必须重新操作才会运动。
- heartbeat：仅暂停心跳并停车，约 3 秒后地面站显示离线；再次 RECOVER 后恢复在线。
- rs485：超时累计增加。
- network：WARN，不代表真实 5G 链路测量。

RECOVER 可以在 Heartbeat 被关闭时调用，因为 Agent 仍运行；Agent 本身退出后，须先重启对应 Agent。

## 6. 记录测试事件

输入事件说明，例如“接触点 P2，第 3 次冲击”，点击对应按钮：

| 按钮 | 用途 |
|---|---|
| TEST START / TEST END | 开始 / 结束一轮测试 |
| EMC START | EMC 阶段标记 |
| EQUIPOTENTIAL CONTACT | 等电位接触 |
| EQUIPOTENTIAL WORK | 等电位工作 |
| MAGNETIC FIELD | 磁场干扰 |
| TEMP HUMIDITY | 温湿度测试 |

Ground 本地记录，并向 A/B 发布同一 event_id、UTC timestamp 和说明。**只有当时在线并收到事件的 Agent 才有记录，离线期间不补发。** 多机部署时必须先由操作者确认系统时间同步。

## 7. 找到日志

默认：`/home/tian/robot_test_system/logs/<session_id>/`。包含 Ground、A、B 各一份 status.csv 和 events.csv。状态每秒记录，事件立即记录并 flush。

建议每轮明确命名：

```bash
cd /home/tian/robot_test_system
export ROBOT_TEST_SESSION=emc_round_001
./scripts/start_mock_demo.sh
```

同名 session 追加写入，适合中途重启；需要新一轮数据时换新名字。CSV 的 value 中包含 JSON 计数。flush 不等于掉电零丢失，完成后请复制整轮日志目录。

## 8. 分开启动和离线验证

三个终端都进入项目目录，并设置同一个 `ROBOT_TEST_SESSION`，分别运行：

```bash
./scripts/start_robot_a.sh
./scripts/start_robot_b.sh
./scripts/start_ground.sh
```

在 A 的终端按 Ctrl+C：约 3 秒后仅 A 离线，B 保持在线；重新运行 A 脚本，Ground 不重启即可恢复。

## 9. 常见问题

| 现象 | 检查方式 |
|---|---|
| GUI 或 ROS 模块找不到 | 使用启动脚本；手动启动前 `source scripts/env.sh` |
| NumPy / OpenCV ABI 报错 | 启动脚本设置 PYTHONNOUSERSITE=1，避免用户级 NumPy 2 覆盖系统库 |
| 配置修改后没变化 | YAML 运行时读取，修改后重启 Agent 和 Ground；不是热更新 |
| 点击 JOG 不动 | 查看是否 OFFLINE、总线/电机故障、服务调用失败；先恢复故障再重新按下 |
| 自动运动不是当前选中的轴 | Auto 使用 YAML 的 auto_cycle.axis |
| 相机只有 7 路 | 检查 A 的 camera_5.enabled 是否为 false |
| 界面没有同时显示完整 | 全屏 F11；目标为 1920×1080 的 Qt 逻辑尺寸，检查桌面缩放是否 100% |
| STOP 服务不可达 | 查看下方错误；本地 Watchdog 是断流保护，服务发送不代表物理停车确认 |

后续参数修改和真实硬件扩展见 [后续配置指南](后续配置指南.md)。

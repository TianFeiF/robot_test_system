# 只有笔记本时怎么测试

可以用内置摄像头验证第一条真实硬件链路：笔记本 UVC 摄像头 → Camera Adapter → Robot A Agent → ROS 图像 topic → Ground 预览和 Diagnostics。其余 7 路相机及全部电机仍为 Mock。

## 一键启动

先关闭已有 Demo，避免同名 A/B Agent 或多个程序争用摄像头，然后：

```bash
cd /home/tian/robot_test_system
./scripts/start_laptop_camera_demo.sh
```

A 的 camera_1 会显示笔记本摄像头画面；标题显示 UVC CAMERA + MOCK MOTORS。当前笔记本已实际识别并测试 `/dev/video0`，640×480，目标发布 5 FPS。启动时指示灯亮起是正常现象；测试程序不保存照片或录像，只记录状态/事件 CSV。

如换 USB 摄像头，可显式指定设备：

```bash
LAPTOP_CAMERA_DEVICE=/dev/video2 ./scripts/start_laptop_camera_demo.sh
```

该示例不表示这台机器的 video2 是普通彩色相机。当前系统有多个节点，部分可能是红外或元数据入口。优先用已经验证的 video0；也可使用 `/dev/v4l/by-id/...-video-index0` 稳定路径。

该脚本生成临时 YAML，退出后清理，不修改原有 A/B YAML。回到纯模拟直接用 `./scripts/start_mock_demo.sh`。

## 你可以按顺序做的测试

1. **画面变化**：在镜头前挥手或移动物体，观察 A camera_1 是否实时变化。确认 frame_count 持续增加、FPS 约为 5，其余 7 路仍是 Mock 图。
2. **遮挡测试**：遮住镜头，再移开。黑画面仍可能正常出帧，因此遮挡不应该等同于 OFFLINE。这个测试验证显示的是实时画面，不是断线检测。
3. **控制并行**：摄像头工作时，按住 Mock drive 的 JOG，确认位置变化；松手、STOP、STOP ALL 都能停车。此步骤验证视频不会阻塞控制，不能证明真实电机已经可控。
4. **Mock 故障隔离**：对 A camera_2 或其他 Mock 相机 INJECT/RECOVER，观察只有指定画面消失/恢复，真实 camera_1 和其余画面继续。真实 UVC 相机不支持 Mock Fault Injection，选择它注入会返回不支持。
5. **断线/恢复**：外接 USB 摄像头可拔插测试自动重连。内置相机不要为了测试去卸载内核模块或改系统设备配置。可先用不存在的设备节点测试失败隔离，见下文；随后用正常节点重新启动。隐私开关有的只遮光，有的断开设备，行为由硬件决定。
6. **Agent 离线**：原纯 Mock 的 A 退出/重启测试仍然适用。离线检测依据 Heartbeat，而不是仅凭视频画面。
7. **持续运行**：运行 20～30 分钟，观察帧数增长、错误/断线计数和窗口响应；这一步需你实际保持运行并检查，本轮短时验收不等于长时间稳定性验证。
8. **日志核对**：点 TEST START、其他阶段标记、TEST END，确认三端 events.csv 一致；检查 robot_a_status.csv 的 camera_1 数据。

内置摄像头不可访问的可控测试（确认先退出正常测试）：

```bash
LAPTOP_CAMERA_DEVICE=/dev/robot_test_missing_camera ./scripts/start_laptop_camera_demo.sh
```

预期 camera_1 OFFLINE，但 A/B Heartbeat、其他 Mock 相机、JOG 和 STOP 仍可用。退出后用正常命令重启即可。不要修改 /dev 权限或创建假设备节点。

## 指标含义与边界

- UVC 的 frame_count 是本 Adapter 成功读取的帧数。
- FPS 是成功取帧频率，不保证等于摄像头硬件采集频率。
- drop_count 是打开/读取失败次数，不是 USB 驱动报告的精确丢帧数。
- disconnect_count / reconnect_count 是本 Adapter 观察到的连接状态变化。
- 请求分辨率未必受所有设备支持，实际 width / height 可在诊断单元格提示和 CSV 中查看。
- 暂时不可用时默认每 2 秒尝试重开。取图调用在独立线程，不阻塞运动 executor；驱动永久卡住时会标记无近期画面，可能需要重启 Agent。
- 本测试验证通用 UVC 彩色摄像头，不能替代 RealSense 深度数据、真实 EtherCAT/CANopen、机器人运动或 EMC 的现场测试。

## 配置原理

临时配置仅改 A 的一路：

```yaml
cameras:
  camera_1:
    enabled: true
    backend: uvc
    device: /dev/video0
    width: 640
    height: 480
    fps: 5
    reconnect_sec: 2.0
    label: LAPTOP CAMERA (LIVE)
```

`backend: uvc` 已实现；原来的 `backend: real` 仍指向尚未实现的 RealSense 等占位后端。Agent 和 Ground 的配置目录通过 `ROBOT_TEST_CONFIG_DIR` 同步，正常使用上述启动脚本即可。
